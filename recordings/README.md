# `recordings/` — captures that go on the map automatically

Drop a Sensor Logger export in here, push it, and
[`process-recordings.yml`](../.github/workflows/process-recordings.yml) scans it and
uploads the findings to the Sidewalk Map. Nothing else is needed: the workflow
runs `bridge scan --format map` on every recording the push added or changed and
POSTs the payload to `scan.ingest`.

A capture the quality gate refuses is reported in the job summary and skipped —
it does not fail the build. Rescanning the same file is safe: the payload carries
bridge's content-hashed `clientScanId`, which `scan.ingest` upserts on, so a
re-run resolves to the same scan and the same reports instead of duplicating them.

## What to commit

- One `.zip` per pass, as Sensor Logger exports it (`Zip of CSVs`), or a
  directory of the CSVs. Name it after the pass:
  `2026-08-29_kings-parade_run-1.zip`.
- Nothing else. Scan output (`*.payload.json`, findings, GeoJSON) is generated by
  the workflow and uploaded as an artifact — it is gitignored, not committed.

### Size

Plain git, no LFS: a 3-5 minute pass at 200 Hz zips to ~5-15 MB, which git
handles fine, and LFS would put every clone and every CI run behind the
repository's LFS bandwidth quota for no benefit at this size. The workflow
refuses any recording over **50 MB** (see the `Guard recording sizes` step) —
GitHub itself rejects pushes over 100 MB, so a capture near the guard is a sign
the pass was far longer than the protocol asks for, and it should be trimmed or
split rather than committed.

## Capture settings (Sensor Logger, iOS/Android)

| Setting | Value | Why |
| --- | --- | --- |
| Accelerometer | **on, 200 Hz** | keeps the 20-80 Hz shock band; ≤40 Hz is rejected, <150 Hz is degraded |
| Gravity | **on** (iOS: same rate) | lets ingest reconstruct total acceleration as `Accelerometer + Gravity` |
| Location | **on, highest accuracy** | findings without a position cannot go on a map; >5 m median accuracy is rejected |
| Everything else | off | smaller export, no effect on the scan |
| Export | **Zip of CSVs** | what this directory expects |

Uncalibrated-only exports work too — `AccelerometerUncalibrated.csv` is in *g*
and is normalised to m/s² at ingest — but `Accelerometer.csv` + `Gravity.csv` is
the unambiguous pair, so leave Gravity enabled.

Recording a pass (route choice, standing still at both ends, how to carry the
phone) is covered in
[`apps/bridge/docs/REAL_WORLD_TEST.md`](../apps/bridge/docs/REAL_WORLD_TEST.md).

## Testing a recording locally

Same two steps the workflow runs, against whichever deployment you point it at:

```bash
pip install -e libs/imukit -e 'apps/bridge[dev]'

SIDEWALK_API_URL=https://sidewalk-map-gamma.vercel.app \
  python apps/bridge/scripts/process_recordings.py \
    --out-dir /tmp/payloads \
    recordings/2026-08-29_kings-parade_run-1.zip
```

Use `SIDEWALK_API_URL=http://localhost:3000` with `npm run dev` to ingest into a
local database instead. To look at a capture without uploading anything:

```bash
python -m bridge.cli scan recordings/2026-08-29_kings-parade_run-1.zip --format map --out /tmp/payload.json
```

`scan.ingest` is a `publicProcedure`, so no token is involved in either case.
